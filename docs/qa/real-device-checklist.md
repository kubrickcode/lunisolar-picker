# 실기기 QA 체크리스트

릴리스 전에 아래 기기에서 문서 사이트(`pnpm --filter @lunisolar-picker/docs dev --host`)를 같은 와이파이로 열어 확인한다. Playwright WebKit은 iOS WKWebView와 같지 않으므로 이 확인을 대신하지 못한다(스펙 11장).

## 기기와 브라우저

| ID | 환경 | 확인 방법 |
|---|---|---|
| iOS-S | iPhone, Safari 최신 | 주소 직접 입력 |
| iOS-K | iPhone, 카카오톡 인앱 브라우저 | 나와의 채팅에 링크를 보내 열기 |
| iPAD-P | iPad, Safari 최신, Apple Pencil | 주소 직접 입력 |
| AND-C | Android, Chrome 최신 | 주소 직접 입력 |
| AND-S | Android(갤럭시), 삼성 인터넷 | 주소 직접 입력 |
| AND-K | Android(갤럭시), 카카오톡 인앱 브라우저 | 나와의 채팅에 링크를 보내 열기 |
| WIN-N | Windows, Chrome 또는 Edge 최신, NVDA | 주소 직접 입력 |
| MAC-V | macOS, Safari 최신, VoiceOver·음성 제어 | 주소 직접 입력 |

각 환경에서 먼저 기록한다: OS 버전, 브라우저 버전, `navigator.userAgent`, `Intl.supportedValuesOf('calendar').includes('dangi')`. (스펙 15장 위험 6)

## 데모 위치

문서 데모는 영어(`en`) 로케일이다. 한국어·음력 항목은 음력 가이드의 데모(`ko`, dangi)로 확인한다.

| 데모 | 경로 | 로케일 |
|---|---|---|
| DatePicker | `/pickers/date-picker/` | en(`MM/DD/YYYY`) |
| DateRangePicker(두 달, 확인 후 반영) | `/pickers/date-range-picker/` | en |
| WheelDatePicker(인라인) | `/pickers/wheel-date-picker/` | en |
| TimePicker(5분 단위, 24:00 허용) | `/pickers/time-picker/` | en |
| 음력 DatePicker | `/guides/lunar-calendar/` | ko, dangi |

## 항목

각 항목을 환경별로 ✅/❌로 기록하고 ❌면 증상과 화면 녹화를 남긴다.

### 1. 세그먼트 입력과 키보드 (스펙 15장 위험 3)

- [ ] 날짜 칸을 누르면 숫자 키패드가 뜬다.
- [ ] DatePicker 데모에서 `03151990`을 이어 치면 `03/15/1990`이 되고 커서가 칸을 자동으로 넘어간다.
- [ ] 삼성 키보드·카카오 키보드(한글 입력 상태)에서도 숫자가 조합 중 상태로 남거나 앞 글자와 겹쳐 쌓이지 않고 바로 들어간다. (AND-S, AND-K)
- [ ] 지우기(백스페이스)로 칸이 비고, 이전 칸으로 돌아간다.
- [ ] `1990-03-15`를 붙여넣으면 세 칸이 모두 채워진다.
- [ ] 음력 데모에서 윤달 토글이 보이고 눌러진다.
- [ ] TimePicker 데모의 시간 칸에 `930`을 치면 `09:30`이 된다.

### 2. 휠 관성 (스펙 15장 위험 4)

- [ ] 연도 열을 세게 튕기면 관성으로 여러 해를 지나 부드럽게 멈춘다.
- [ ] 멈춘 뒤 가운데 줄에 정확히 맞춰진다(반 칸 걸림 없음).
- [ ] 휠을 굴리는 동안 페이지나 시트가 같이 스크롤되지 않는다.
- [ ] 60fps에 가깝게 보인다(끊김을 느끼면 ❌). 중저가 Android 한 대 이상 포함.
- [ ] (음력 휠 데모 필요) 음력 모드에서 연도를 바꿔 윤달이 사라지면 월이 평달로 옮겨진다. 문서에는 음력 휠 데모가 없으므로 확인 전에 데모를 더하거나 사용하는 앱에서 확인한다.

### 3. 시트와 스크롤 잠금

시트는 손가락 입력이면서 폭 640px 이하인 화면(`(pointer: coarse) and (max-width: 640px)`)에서만 뜬다. 태블릿 가로 화면에서는 팝오버가 정상이다.

- [ ] 휴대폰에서 DatePicker를 열면 아래에서 시트가 올라온다.
- [ ] 시트가 열려 있는 동안 뒤 페이지가 스크롤되지 않는다.
- [ ] 시트를 닫으면 원래 스크롤 위치로 돌아온다(iOS에서 맨 위로 튀지 않음). (iOS-S, iOS-K)
- [ ] 카카오톡 인앱에서 시트 안 휠을 굴려도 인앱 브라우저의 당겨서 닫기·새로고침이 일어나지 않는다. (iOS-K, AND-K)
- [ ] 화면 키보드가 올라와도 시트의 확인 버튼이 가려지지 않는다.

### 4. 범위 선택 (터치·펜)

- [ ] 시작일과 종료일을 차례로 탭하면 범위가 선택된다.
- [ ] 달력 위에서 손가락을 끌면 범위 선택이 아니라 페이지가 스크롤된다.
- [ ] Apple Pencil로 시작일에서 종료일까지 끌면 범위가 선택되고, 손을 뗀 뒤 누른 날 하루짜리 범위로 바뀌지 않는다. (iPAD-P, 스타일러스가 있는 Android)
- [ ] Apple Pencil로 날짜를 탭만 해도 하루짜리 범위가 바로 확정되지 않고 종료일을 기다린다. (iPAD-P)
- [ ] 확인 후 반영 모드에서 Cancel을 누르면 원래 범위로 돌아간다.

### 5. 다크모드와 고대비

picker는 OS 설정을 스스로 따르지 않고 조상의 `data-theme`·`.dark`를 따른다. 문서 사이트는 Starlight 테마 선택에 따라 `html`의 `data-theme`를 `light`·`dark`로 바꾼다.

- [ ] 문서 사이트 테마를 Auto로 두고 OS 다크모드를 켜면 picker가 어두워진다.
- [ ] 문서 사이트 테마 전환(Light·Dark)에 맞춰 picker가 바뀐다.
- [ ] 다크모드에서 시트·팝오버 배경과 글자 대비가 충분하다(흰 배경 섬광 없음).
- [ ] Windows 고대비(대비 테마)에서 선택한 날짜·범위·포커스 링·비활성 날짜가 구분된다. 앱이 그린 장식(예: 공휴일 점)이 선택 날짜 위에 일부 남는 것은 알려진 한계다. (WIN-N, `/parts/calendar/`도 확인)

### 6. 스크린 리더

- [ ] VoiceOver(iOS)로 달력 날짜를 넘기면 전체 날짜가 읽히고, 음력 데모에서는 음력 날짜가 읽힌다.
- [ ] TalkBack으로 휠 열을 조작하면 숫자 위치가 아니라 열의 텍스트 값(예: "March", "1990")이 읽힌다. 음력 휠의 "윤4월"은 음력 휠 데모가 생기면 확인한다.
- [ ] 월을 넘기면 달력 제목(예: "April 2026")이 한 번 읽힌다. 이전·다음 버튼 안에서 같은 문구가 두 번 읽히지 않는다. (VoiceOver, NVDA)
- [ ] 읽기 전용 달력·칸이 "읽기 전용" 또는 "흐리게 표시됨"으로 읽히고, 날짜를 고를 수 있다고 안내되지 않는다. (VoiceOver, NVDA)
- [ ] 빈 날짜 칸은 값 문구로 placeholder("MM", "DD", "YYYY")를 내보낸다. 실제로 어떻게 읽히는지 적고, 값이 있는 것처럼 오해되면 ❌. (VoiceOver, NVDA)
- [ ] 시스템 "동작 줄이기"를 켜면 월 전환·팝오버 애니메이션이 없고, 휠은 손을 떼면 미끄러지는 애니메이션 없이 바로 가운데 칸에 맞춰진다.

### 7. 음성 제어 (#D9)

한국어 날짜 칸의 접근 가능한 이름은 "2026년 10월 20일 화요일"이고 보이는 글자는 "20"이다. axe는 이 조합을 WCAG 2.5.3 위반으로 보지만 ko만 예외로 두었다.

- [ ] macOS 음성 제어(한국어)에서 음력 데모 달력을 열고 "20 클릭"이라고 말하면 20일이 눌린다. (MAC-V)
- [ ] 안 되면 "20일 클릭"도 시도해 결과를 적는다. 둘 다 안 되면 ko 로케일의 날짜 이름을 "20 일"로 띄어 쓰는 수정을 검토한다.
